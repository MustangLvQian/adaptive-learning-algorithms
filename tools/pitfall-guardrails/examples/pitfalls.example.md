# 踩坑登记表（示例）

这份文件是踩坑的**唯一**权威来源。规则：同一个坑第二次出现，必须留下守卫。

## 守卫命令

| 命令 | 覆盖 |
|---|---|
| `npm run check` | 静态检查与结构校验 |
| `npm test` | 单元测试与逻辑回归 |

## PWA / Service Worker

| ID | 症状 | 根因 | 规则 | 守卫 | 来源 |
|---|---|---|---|---|---|
| PWA-01 | 装好后离线一切正常，就是没声音 | 预缓存清单 `CORE_ASSETS` 漏了运行需要的音频 | 离线要用的每个资源都要能被解析 | `✅` `npm run check` | 实测 |
| PWA-02 | 部署后装了 PWA 的机器一直看到旧界面 | 导航请求走 cache-first，被钉在安装时的版本 | 导航请求一律 network-first | `✅` `npm run check` | 实测 |
| PWA-03 | 更新一来就刷新，语音被切断 | 检测到更新就 `skipWaiting` + 立即 reload | 更新只在空闲态应用 | `manual` | 实测 |

## 工作流 / 环境

| ID | 症状 | 根因 | 规则 | 守卫 | 来源 |
|---|---|---|---|---|---|
| WF-01 | `git push` 卡住、443 超时 | 本机访问不了 `https://github.com` 但 SSH 通 | origin 用 SSH，`git pull` 一律 `--rebase` | `◐` `npm run check`（只覆盖配置，方向靠人） | 实测 |

## 怎么加一条

1. 先查有没有同 ID / 同症状；有就更新，不要新建重复项。
2. 能自动化的写检查，把命令填进「守卫」列。
3. 不能自动化的，守卫写 `manual`，并在规则里写清人工步骤。
